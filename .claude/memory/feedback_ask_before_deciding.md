Always ask before making architectural or design decisions on this project.

**Why:** The user explicitly stated in PROJECT_KNOWLEDGE.md: "The user wants to be asked before making decisions — do not assume."

**How to apply:** When a task has multiple valid approaches (e.g., refactor strategy, new feature design, API shape), present the options and get confirmation before writing any code. For bug fixes with a clear single solution, proceed but explain what you're doing.
